LastCall

가까운 응급실과 응급 행동을 한곳에 연결하는 모바일 서비스

현재 위치와 검색 조건을 바탕으로 주변 응급실을 빠르게 찾고, 지도·전화·위치 공유·의료정보·커뮤니티까지 응급 상황에 필요한 흐름을 하나의 앱으로 연결한 프로젝트입니다.

01 · 프로젝트

검색보다 먼저
응급 행동을 안내

응급 상황에서 병원 정보를 찾는 단계를 줄이고, 사용자가 다음 행동으로 바로 이어지게 합니다.

위급 증상 안내와 119 전화가 홈 최상단에 있고, 위치 기반 조회가 어려울 때는 지역 직접 검색으로 전환할 수 있습니다. 제공 정보는 의료진이나 119의 판단을 대신하지 않는다는 안전 고지도 함께 제공합니다.

05 · 설계 판단

신뢰할 수 없는 정보는
기능보다 먼저 제한

위치·개인정보

위치 동의를 선택 사항으로 분리하고 재고지합니다. 의료정보는 기기에 보안 저장하며, 서버 접근 로그에서 위·경도 쿼리를 제외하고 보관 기간을 제한했습니다.

콘텐츠·관리자 보안

게시판 운영정책 확인, 게시글·작성자 숨김, 신고 처리 기능을 적용했습니다. 관리자 비밀번호는 BCrypt 해시로 설정하고 토큰 세션과 요청 제한을 사용합니다.

AED 범위 판단: 공공데이터 API의 실제 응답 필드와 신뢰성이 확정되기 전에는 검색 기능을 제공하지 않고 준비 화면과 119·응급 대처 안내만 제공합니다.

06 · 개발 과정

실기기 오류를
운영 로그까지 추적

  1. 응급 행동·검색·상세·커뮤니티 사용자 시나리오와 안전 고지 정의
  2. 공공데이터 실제 필드에 맞춰 앱 파라미터, 컨트롤러, 서비스 필터를 함께 설계
  3. Expo 앱과 Spring Boot API, MyBatis·MySQL 기반 커뮤니티 기능 구현
  4. 네이버 지도, 위치 권한, 외부 지도·전화·공유 등 네이티브 흐름 연결
  5. 웹·Android 번들·서버 테스트와 운영 HTTPS API 호출로 반복 검증
  6. 실기기 게시판·관리자·안전영역 문제를 Nginx 로그와 회귀 테스트로 보완

08 · 성장

기능 구현에서
운영 책임까지

외부 API와 위치 데이터는 정상 응답만으로 충분하지 않았습니다. 실패·지연·권한 거부·오래된 병상 정보까지 사용자 경험의 일부로 보고, 서버 중계·캐시·재시도·안전 문구·로그 비식별화를 함께 설계했습니다. 이를 통해 모바일과 백엔드를 잇는 구현 역량뿐 아니라 의료정보 서비스가 요구하는 보수적인 범위 판단과 운영 검증의 중요성을 익혔습니다.
